# 编辑时门 · 工作规程（S1v2/T9 · 总工单 G2："生成时管"缺失→门往前移一格）

> 依据：《总工单-AI写项目缺陷防治-20260923.md》G2——P4/P8 的教训是"事后查
> 不如生成时管"。本区既有哲学（本地 pre-commit=糖）升级一格：
> **生成期 → 【编辑期】 → 提交期 → CI 期**，本件补的是**编辑期**。

## 规程（每次编辑保存后，不等提交）

1. **跑门**（对被编辑文件）：
   ```bash
   py -X utf8 tools/code_quality_gate.py <被编辑文件> [--allow <仓内模块>]
   py -X utf8 tools/smell_scan.py <被编辑文件>
   ```
2. **跑被测物的测试**（改 evocore → `cd evocore/tests && py -X utf8 -m unittest`；
   改 audit-kit → 对应套件；改工具 → 手工跑一条真实调用）；
3. **违规回喂**：门/测试的**原文输出**贴回上下文，改到过为止——**不许**把
   "已修复"作为结论（AI 会说"已修复"然后不改：配置单原则①的实证）。
4. 涉及"行为必须不变"的重构（如 S1v2/T1/T2）：加跑
   `py -X utf8 tools/S1_verify_behavior.py` 作接受面（差异 0 才算过）。

## 与提交门的关系

| 层 | 工具 | 强度 | 何时 |
|---|---|---|---|
| **编辑期（本件）** | `code_quality_gate` + `smell_scan` + 测试 | 反馈回路（不拦截，但每编辑必跑） | 每次保存后 |
| 提交期（既有） | `.git/hooks/pre-commit`（append-only/LOG 撞号/R2/副本一致性） | **硬拒**（exit 1） | 每次 commit |
| 交付期 | 各 S 步的验收件（如 S1 三层验收） | 硬拒+人读 | 每步交付 |

## 例外与登记（全部要留痕，不许静默绕过）

- 存量大文件/既有站点：`--legacy`（跳门①⑥）；
- 合规安全站点：行内 `# sec-exempt: <理由>`（理由非空才生效）；
- 已确认接受的坏味：`tools/smell-baseline.txt` **带理由**登记（修掉后删行）；
- 任何上述豁免在 commit message 或 LOG 条目里**可见**。
