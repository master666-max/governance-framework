# 架构书 · evo-seat 微型内核（v1，2026-09-23，审计区设计稿）

> 用户令："保持现在这个架构，再提出一版微型内核——集成化、小型化、直接包含
> 治理框架与演化内核、融合在一起、提供丰富的审查精细度档位。"
> 性质：与 v4.3 双包体系**并存的另一形态**（不替代）；单文件分发传统（bootstrap
> 血统）× 治理融合 × 档位制（audit-seat 血统）。

## 一、定位：三个形态一张表

| 形态 | 适合 | 强制力 |
|---|---|---|
| **v4.3 双包**（audit-kit+memsys） | 多宿主、多 Agent、跨平台、要独立发布框架 | 全量（双进程 CI/能力令牌/import-linter/MCP） |
| **evo-seat 微型内核**（本版） | **单人/单项目/单文件投递**——一个知识库要"装上就有治理+演化" | **六档可调（G0-G5）**，本地单进程 |
| 旧 v3.9 | 已被两形态取代 | — |

**evo-seat 的本质**：把 audit-kit 的治理与 evocore 的演化**融合进一个单文件**
（bootstrap 单文件分发血统）——牺牲多宿主/多平台，换来**一个文件、零依赖、
零部署、按档取用**。

## 二、单文件分区（集成化的形态）

```
evo_seat.py（单文件投递，目标 ≤1200 行）
  §0 SOURCES 区        版本/档位定义/参数（唯一事实源，文档由它渲染）
  §1 core              类型（frozen dataclass 构造校验）+ 链哈希
  §2 store             SQLite events 表 + 触发器物理 append-only + 链重放验证
  §3 rank              演化：五参数精排 + bigram 分词 + recall 接口（向量插座）
  §4 lifecycle         演化：三态 + tombstone + last_used 衰减 + 类型曲线
  §5 decide            演化：三 intent 规则版（LLM tool call = G4 档接入点）
  §6 gates             治理：质量门（长度/语句/分支/import 白名单/静默失败）
                       + 锚验证 + 出站扫描（三态）——按档位启用
  §7 cli               init / append / retrieve / promote / tombstone /
                       verify / audit / level（档位切换）
  §8 tests             内嵌自注册测试（G1 起每次 verify 顺跑）
  §9 main              档位解析 + 分发
```

**集成化的纪律代价**：单文件内**区段即边界**——区段间只许单向调用
（cli→gates/decide→rank/lifecycle→store→core），违约由 §8 内嵌测试断言
（import-linter 的单文件替身：**区段依赖测试**）。

## 三、审查精细度档位（本版核心：G0–G5 六档）

| 档 | 名 | 装什么 | 强制力 |
|---|---|---|---|
| **G0 观察位** | events 账本 + 检索 + 三态 | 触发器物理 append-only（唯一内置强制） | 违规无门，但**账永远是真的** |
| **G1 标准位** | + 链重放验证 + 墓碑 + 开库即验 | verify 进每次 open（fail-closed） | 坏库不许用 |
| **G2 类型位** | + 条目 schema 构造校验 + 类型差异化衰减 | 非法条目**建不出来**（P7 结构优先） | 脏数据无载体 |
| **G3 门位** | + 质量门五道 + pre-commit 接线 + 区段依赖测试 | 提交前自动拦一道 | 机械违规当场拒 |
| **G4 决策位** | + 决策留痕 + 金标机器（挣得管辖）+ defer 率监控 | LLM 按金标挣得，规则兜底 | 不可复算层被金标压住 |
| **G5 锚定位** | + 入库锚（commit trailer）+ 出站扫描三态 + 每周巡检 | 全部强制力在位 | 完整治理 |

**档位语义**：①单调向上（G_n ⊃ G_{n-1}，切换= `evo level G3`，降级留痕）；
②**每档都是完整可用的终态**（G0 不是"没装完"，是"只要账"的正当选择）；
③`VACUOUS/SKIP/N/A` 三符号跨档一致（"这一格没被检查过"≠通过）。

## 四、微型化的取舍（诚实对照 v4.3）

**砍掉的**（及代价）：
| 砍 | 代价 | 补偿 |
|---|---|---|
| 双包独立发布 | 框架不能单独给别人装 | 裁剪矩阵：真需要框架→升 v4.3 |
| MCP server 进程 | 无跨平台接入 | cli 直用；MCP 桩留 §7 |
| 能力令牌运行时签发 | 无多写者权限面 | 单人单机无此需求；档位=静态权限 |
| import-linter 四契约 | 分层靠自觉 | 区段依赖测试（§8）机械兜底 |
| 金标自动生长/每周强制复盘 | 金标靠手动标 | G4 保留 30 例冷启动+挣得判据 |
| RFC 3161/公开账本锚 | 锚=git trailer+本地远端 | G5 起步够用，强锚插座保留 |

**绝不砍的**（微型化的底线）：
触发器物理 append-only · 出处三件套 · fail-closed · 墓碑不删 · 决策留痕 ·
构造时校验 · 内嵌测试——**小的是体积，不是纪律**。

## 五、分期（M0-M3）

| 期 | 交付 | 门 |
|---|---|---|
| M0 | §0-§2（SOURCES/core/store）+ G0-G1 可用 | 触发器 ABORT+链重放测试绿 |
| M1 | §3-§4（rank/lifecycle）+ G2 可用 | 检索与衰减不变量绿（类型曲线/procedural 零衰减） |
| M2 | §6-§7（gates/cli）+ G3 可用 | 质量门自食（对 evo_seat.py 本文件跑）+ 区段依赖测试 |
| M3 | §5（decide）+ G4-G5 + 全档切换测试 | 档位矩阵测试（6 档×核心操作）+ 决策留痕在案 |

## 六、与 v4.3 的关系条款

- 并存不互斥：v4.3 是"重装全套"，evo-seat 是"轻装上阵"；**共同纪律子集**
  （append-only/锚/fail-closed）两形态语义一致，升级路径=evo-seat 的 events
  表可直迁 v4.3 的 SQLite（同 schema 演化）；
- 演化机制的**行为语义**（五参数/类型曲线/三态/挣得判据）两版保持同源——
  evo-seat 的 G4 判据引用 memsys/prereg 同一份（预注册不分家）；
- blender-kb 类轻宿主：**evo-seat 是它们的默认形态**（单文件进 skill 目录
  即得），v4.3 留给 memsys 级重宿主。

## 七、验收判据

1. 单文件 ≤1200 行 + 质量门自食通过（对 evo_seat.py 跑五道门）；
2. 六档矩阵测试：每档核心操作全绿 + 降级留痕；
3. 触发器 ABORT/链重放/墓碑不删/构造校验四不变量在**每一档**都成立；
4. G4 决策留痕抽样在案；G5 锚比对通过；
5. 内嵌测试随 verify 顺跑（丢档不丢测试——测试跟着文件走）。
