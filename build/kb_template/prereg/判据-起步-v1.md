# 判据 · 起步（本库预注册件 v1）

> 生效：2026-09-23。版本：v1。判据锚：kb-starter-v1
>
> 性质：**预注册件**（SPEC §B-3 判据注入）。本件先于任何命中它的决策而冻结；
> 改判据 = **新增 `-v2` 文件**，不改本件（append-only 精神）。
> 本件的存在同时满足体检的机械格式要求（版本行 + 生效日行；见 `gov/core/prereg.py`）。

## 一、起步期的判据内容（诚实声明：本库尚未注入领域判据）

本库起步阶段**沿用框架默认**，不另立领域阈值。具体：

| 面 | 起步取值 | 出处 |
|---|---|---|
| `severity_if_wrong` 判例 | 规则版：`conflict` 且涉 `source=manual` → `irreversible`；其余 → `redundant` | `evo/evocore/decision.py::_trace` |
| 晋升阈值 | `TUNABLES.promote_importance_min`（默认值，不外改） | `evo/evocore/tunables.py` |
| 衰减乘数 | `TUNABLES.decay_mult_*`（默认值，不外改） | 同上 |
| 人工录入零容忍面 | 凡 `source=manual` 的条目，自动决策错判**一律升格** `irreversible` | `decision.py`（判例法补充） |

**这不是"没有判据"**——它是一份写明"起步期以框架默认为准"的判据件：决策留痕的 `prereg`
字段会带上 `kb-starter-v1`，读账即知这条判定依据的是哪一份、哪一版。

## 二、什么时候必须新增领域判据件（触发器）

出现以下任一情况，须**新增** `prereg/<名>-v1.md`（不改本件），并在其中写清判例与阈值：

1. 本库出现框架默认判不了的错判类型（例如领域内"错一次不可逆"的语义与默认规则不同）；
2. 需要与 `TUNABLES` 默认不同的晋升/衰减阈值（写清差异与理由）；
3. 决策层从规则版切换到 LLM 接管（须先有金标判据——范例见 `memsys/prereg/金标判据-v1.md`）；
4. 多写者接入（L2 化）：需要来源可信度分级与冲突裁决顺位。

## 三、写法要求

见本目录 `README.md` 的「机械格式」节（`conformance --kb` / `--host` 强制：件首元数据区须有
版本行与生效日行；缺项即 FAIL）。本件不在这里复述写法示例——**示例文字会被自己的格式检命中**，
这是本批负向对照抓到的真坑（`audit-kit/core/prereg.py::HEAD_LINES` 有案）。
