# prereg/ · 判据注入位（L2 服务件骨架 · S8-5）

> 依据：SPEC §B-3（判据注入=宿主三件事之三）。L2 形态下「宿主」=服务件（运营域级），
> 本目录承载**本运营域自己的领域判据**——先于实现的预注册件。
> 决策留痕（`memory_adjudicate`）的 `prereg` 字段会带上本目录里合格判据件的锚
> （`<名>@<版本>`）；**本目录为空或都不合格时该字段为 `null`**——读账即知
> 「这条判定当时没有判据可依」。这就是"判据先于实现"落到每条决策上的方式。

## 机械格式（体检强制，缺项即 FAIL）

每份判据件（`prereg/*.md`，`README.md` 除外）必须能被机械抽出两项：

| 必检项 | 认的写法 | 例 |
|---|---|---|
| **版本行** | `版本：` / `版本:` / `version:` | `> 生效：2026-09-21。版本：v1。` |
| **生效日行** | `生效：` / `生效日期：` / `effective:` + ISO 8601 | 同上 |
| 引用锚（可选） | `判据锚：<id>` | `判据锚：ops-gold-v1` |

- 缺任一项 ⇒ `conformance --kb` / `--host` 报 **FAIL**（不是"目录非空"就算有判据）；
- **引用锚默认机械派生** `<文件名>@<版本>`；件内自带 `判据锚：` 时以它为准
  （好处=文件改名/移动而引用不断）；
- 多份合格判据件时，留痕指针取**字典序首份**（确定性）；一域一判据件为常态，
  多份时其余须在件内互相引用；
- 改判据 = **新增文件**（`-v2`），不改旧件（append-only 精神）；旧件留在目录里即历史。

## 本域要写什么（按需，起步可空）

1. **severity_if_wrong 判例**：本域哪些错判"不可逆"（`irreversible`）、哪些"可被下次纠正"（`redundant`）；
2. **晋升/退役阈值**（若与 `evo/evocore/tunables.py` 默认不同，写清差异与理由）；
3. **人工录入的零容忍面**（哪些来源=manual、错判一律升格）；
4. **运营域级附加面**（L2 特有）：多写者冲突的裁决顺位、来源可信度分级、
   跨库引用的采纳门槛——完整版来源审计视图归 L2-2（裁定索引 §一 第 13 行）。

范例（完整形态）：`memsys/prereg/金标判据-v1.md`。
机械判据实现：`kernel/core/prereg.py`（服务件自带的治理核副本内）；
负向对照测试：`build/tests/test_prereg_gate.py`（删掉版本行必须 FAIL）。
