## 二、数据模型：非法状态不可表示（P7）

### 2.1 账本事件（audit-kit/core/gov_types.py）

```python
@dataclass(frozen=True)
class Event:
    seq: int; ts: str; actor: str; kind: str
    payload: dict; prev_hash: str; self_hash: str

    def __post_init__(self):
        if self.seq < 1: raise ValueError(...)
        if not _ACTOR_RE.match(self.actor):          # 'llm:x'|'fallback:rule'|'human:a'|'ci:hook'
            raise ValueError(f"actor 须形如 ... 得 {self.actor!r}")
        ...
        for name in ("prev_hash", "self_hash"):
            h = getattr(self, name)
            if len(h) != 64 or any(c not in "0123456789abcdef" for c in h):
                raise ValueError(f"{name} 须 64 位小写十六进制")
```

**设计语义**：字段约束**在构造时**生效（frozen dataclass `__post_init__`）——
非法事件对象**无法存在**，而不是"存在后被查出"。（B1 修正：不使用虚
`Annotated` 元数据——那是给运行时校验器读的注释，本身不拦。）

### 2.2 能力令牌（同文件）

```python
@dataclass(frozen=True)
class Capability:
    resource_kind: str
    scope: Scope
    can: frozenset[str]
    cannot: frozenset[str] = frozenset()
    expires: str | None = None

    def __post_init__(self):
        ...
        overlap = self.can & self.cannot
        if overlap: raise ValueError(f"can/cannot 交集非空：{sorted(overlap)}")
        if self.expires is not None:
            if not _DATE_RE.match(self.expires): raise ValueError(...)
            try: datetime.date.fromisoformat(self.expires)   # 日历合法性
            except ValueError as e: raise ValueError(f"expires 非法日历日期...") from e
```

`can ∩ cannot = ∅` 在构造时强制——它使运行时的 CANNOT 检查成为**纵深防御**
（对绕过构造的鸭子类型对象生效），真实对象该分支不可达（R2-2/R2-3 豁免登记
的依据，`tools/invariant-findings-ledger.md` §四）。

## 三、哈希与链（audit-kit/core/hashes.py）

```python
def canonical_json(obj) -> str:
    return json.dumps(obj, ensure_ascii=False, sort_keys=True, separators=(",", ":"))

def event_hash(prev_hash: str, payload, actor: str = "", kind: str = "") -> str:
    # v2：actor/kind 并入哈希输入——头部字段篡改可检出（20260923 评审采纳）
    if len(prev_hash) != 64 or any(c not in "0123456789abcdef" for c in prev_hash):
        raise ValueError(...)
    body = canonical_json({"actor": actor, "kind": kind, "payload": payload})
    return hashlib.sha256((prev_hash + body).encode("utf-8")).hexdigest()

GENESIS = "0" * 64
```

**机制**：`self_hash = sha256(prev_hash ‖ canonical_json(payload))`。
规范 JSON（键排序+无空白）保证同一 payload 恒同一字节串；prev 衔接使每一行
依赖上一行——**改历史行=其后全链重算**，而重算检出靠库外锚（§八）。

## 四、append-only 物理强制（audit-kit/ledger/schema.sql）

```sql
CREATE TRIGGER IF NOT EXISTS no_update
BEFORE UPDATE ON events
BEGIN SELECT RAISE(ABORT, 'append-only: events 表禁止 UPDATE'); END;

CREATE TRIGGER IF NOT EXISTS no_delete
BEFORE DELETE ON events
BEGIN SELECT RAISE(ABORT, 'append-only: events 表禁止 DELETE'); END;
```

**验证（test_auditkit.py）**：外部连接执行 `UPDATE`/`DELETE` →
`sqlite3.IntegrityError`（物理 ABORT，非应用层约定）。

**开库顺序敏感（测试抓出的真 bug）**：`open()` 对**既有库先验触发器再执行
schema**——否则 `CREATE TRIGGER IF NOT EXISTS` 会把被摘除的触发器**静默重建**
掩盖破坏：

```python
preexisting = os.path.isfile(path)
conn = sqlite3.connect(path, isolation_level=None)
if preexisting:
    cls._require_triggers(conn)   # 触发器缺失 ⇒ LedgerError，拒绝重建掩盖
```

## 六、能力令牌四关（core/capabilities.py）

```python
def check(cap, action, ref, now=None) -> Verdict:
    if action not in cap.can:   return Verdict("capability", False, "DENY:NO_CAP ...")
    if not cap.scope.matches(ref): return Verdict("capability", False, "DENY:SCOPE ...")
    if action in cap.cannot:    return Verdict("capability", False, "DENY:CANNOT ...")
    if cap.is_expired(now):     return Verdict("capability", False, "DENY:EXPIRED ...")
    return Verdict("capability", True, ...)
```

四关**顺序即契约**（先查持有没有、再查越界、再查显禁、再查过期）；拒因
可机读前缀让消费者不解析散文即可分类。签发本身产出
`kind='capability_issue'` 事件——**权限的历史也在账本里**。

## 七、演化机制（evocore · S1 起平自 memsys/engine）

### 7.1 检索：分词 → 打分 → 平局破序（evocore/retrieval.py）

- **分词**：CJK bigram + 西文小写（`_tokens`；混排切分与 v3.9 逐位对齐留
  W4 双跑门，已登记）；
- **五参数线性打分**（全部外置 `Tunables`，构造校验）：

```python
s = w_kw * kw_hit + w_content * content_hit + w_imp * importance
s -= w_age * age_days * decay_multiplier(entry)     # 按类型差异化
if entry.get("tombstone"): s = 0.0                  # 墓碑恒 0
```

- **类型衰减曲线**：episodic ×2（快）/ semantic ×1 / **procedural ×0（零
  衰减）**——"配方永不过期"由乘数结构保证，非调参；
- **确定性平局破序**：`sorted(key=(-score, id))`（v3.10/W-5 语义）；
- **召回接口**：`recall()` 现役=词面全量；向量召回按触发器挂载
  （≥100 分层实测掉亚族带外才装——不掉不装）。

### 7.2 生命周期（evocore/lifecycle.py）

| 操作 | 语义 | 留痕 |
|---|---|---|
| `route(entry)` | importance ≥7 → longterm（R5 起改决策层挣得） | — |
| `promote(entry)` | intermediate→longterm | `kind='promotion'` |
| `attic(entry, reason)` | 回退=移 attic 并登记（**公理 F：禁销毁式回退**） | `kind='attic_nomination'` |
| `tombstone(entry)` | 退出检索、原位保留 | `kind='tombstone'` |
| `touch(entry, ts)` | **被检索命中即刷新 last_used_at** | 检索命中事件 |

**衰减模型**：`age = now − last_used_at`——常用不忘、不用才淡
（MemoryBank 验证解），拆掉 created_at 线性定时炸弹（v3.9 病灶：40 天→
−4 分压过全部正权重）。

### 7.3 决策层（evocore/decision.py）——LLM 挣得管辖

```python
def _trace(intent, entries, decision, rationale):
    return {"kind": "memory_adjudicate", "intent": intent,
            "entries": [...], "decision": decision, "rationale": rationale[:200],
            "ts": _now(), "actor": "fallback:rule",
            "severity_if_wrong": "irreversible" if ...manual... else "redundant"}
```

- **conflict**：v1 规则 manual > importance > created_at；**含 manual 条目的
  错判一律升格 irreversible**；
- **merge**：v1 **保守拒绝**（defer）——"同义判断写不成规则"，defer 率 >40%
  触发复审（防刷通过率）；
- **promote**：阈值进 TUNABLES（不再硬编码）；
- **LLM 接管路径（W7/金标判据 v1）**：`severity_if_wrong: irreversible` 错误
  率 ≤5% 且 manual 零误伤才挣得；管辖范围=双跑差异清单圈定的残余案例；
  **扩张=新一轮挣得**；LLM 决策**只能重读、不能重推**（不可复算性已入边界）。

## 十一、边界与诚实声明

1. LLM 决策**不可复算**（只能重读不能重推）——金标挣得是信任重建机制，
   不是消除；
2. 金标 ground truth = **用户偏好**，换用户重标；模型换版=新一轮挣得；
3. **锚保完整性不保正确性**（防篡改不防"记错了"）；词面检索天花板已定
   触发器（≥100 分层实测）；**锚的独立性边界**：自举账本与锚同机同盘，防
   "顺手篡改"不防持根权限攻击者（v1 接受，强锚插座预留）；**并发边界**：
   单写者 v1 无竞态面，多写者需事件流合并或独占写进程（登记待 v2）；
   **阈值依据**：≥100 分层实测/≤5% irreversible/40% defer 三条均为预注册
   先验，首轮回测后修订；**墓碑排序语义**：墓碑(0 分)与负分条目同不召回
   （retrieve 过滤 >0），语义一致已钉死测试；
4. CJK-ASCII 混排分词缺口已登记（W4 双跑门对齐项）；
5. 本文档也会过期：一切以仓内文件与 144 项测试的实际输出为准。
