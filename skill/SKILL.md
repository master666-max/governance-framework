# 自演化知识库构建体系 v1.0（Self-Evolving KB Skill）

## 第一步：判断该不该用（30 秒，不满足就退出）

依次回答：
1. 产品能不能跑自动化测试？→ **能：退出**，去写 CI（本体系是 CI 的劣化手工版）。
2. 只有单一生产者、用不了 6 个月？→ 退出，或只装最小件（见 `templates/`）。
3. 真值可以直接观测（传感器/日志/流水）？→ 退出，直接测。
4. 处于高速创意探索期？→ 退出（预注册门会杀死探索分支）。
5. 生产者不可信 + 多代理并发 + 产品是知识 + 人不能全程在场？→ **继续**。

详见 `references/说明书v2` 第零章（含 break-even 门槛：≥3 生产者×≥6 月×单错≥一人周）。

## 第二步：安装（一条命令）

```
sh install.sh <你的知识库目录>
```

生成 MVP 六件：账本（九列 schema）/supersede 侧表/事故表/审计表/锚点协议/
预注册 SOP v1.2 模板。装完自动五项自检（全 PASS 才算装好）。

可选治理仪器（推荐，装前读 `references/说明书v2` 第五章）：pre-commit 治理
钩子（append-only+撞号+副本一致+R2 闸门）/invariant_scanner（死字段+恒真
断言扫描）/constants-registry（冻结常数配方簿）/findings-ledger（检出处置
台账）。

## 第三步：开始第一波（核心循环）

拟题 → 预注册（SOP 五条款缺一不受理；门值引用三要素：带表+亚族名+锚点）→
执行（双跑对照+逐位宣称必附豁免清单）→ 回执 → 同深度验收（锚点+数字独立
复算+双跑 cmp+artifact 在案）→ 入账（R7 追加，幂等键查重）。

日常运转细节与每步失效模式：`references/说明书v2` 第三章。

## 铁律（违反即体系失效）

1. **账本 append-only**：只追加与超越，永不修改；修正走 supersede 侧表。
2. **锚点唯一寻址**：file@commit:line + 逐字摘录；裸行号在活文件上半衰期
   以小时计。
3. **覆盖边界外不称"不存在"**；缺失不配机制解释；证据不足不配严重度。
4. **计数必带基准**：模式/路径域/命中类型三元组。
5. **哈希声明基准态**（blob/工作树）；验证判定绑 blob 不绑文件名。
6. **裁决权归人**：矛盾登记不合并（CONTESTED）；AI 有叫停权无推进权。

## 免疫（失效如何变成规则）

事故 → 登记（incident-log）→ 条款化（进 SOP/钩子）→ 行为采纳（下一份
预注册即视为采纳）。强制力自测：你写下的规则在五级阶梯的哪一级？
⑤ 文档纪律 / ④ 门 / ③ 可机械否证 / ② 运行时崩溃 / ① 类型不可表达——
**尽量往右搬**。详见 `references/说明书v2` 第五章。

## 已知边界（诚实声明）

- 提取员方差噪声底 46.7%（n=1）：一切计数用区间解读；
- 双盲交集消灭提取方差，**不消灭共同理解错误**；
- 说明书自身也会过期：复核任何声称须带 commit。
