# 教学案例 1 · 评测仪器如何抓出自己的缺陷（072① 全链，2026-09-19）

> 用途：演示"分歧监控→口径澄清→验收抓错→实证缺陷→结构修复"的完整循环。
> 教学点：**仪器的缺陷由仪器自己的读数暴露**——这不是意外，是分歧监控的
> 设计目的。

## 第一幕 · 触发

带表 v3 首次跑"分线分歧监控"：把每条线的自身读数分布与混合带比较。线B线
mechanical q25=.175 落在混合带区间 [.482,.726] 之外——**自动触发上报**
（预注册条款：线内 q25 落带外即上报）。

## 第二幕 · 口径澄清（一线在预注册前主动来问）

"预注册引用带值时，混合带门值和线B线单独分布是两个口径，怎么用？"
——审计区发澄清件：**判定门唯一=混合带**；线内分布只是参考，预注册必须
带"混合带"字样+锚点；若读数落在两口径之间（.175–.482 分歧区间），官方按
混合带判、双口径一并呈报。

## 第三幕 · 验收抓错（下一版带表翻车）

带表 v4 交付。验收时发现：线B旧样本池被手抄错——漏了 E108 的 .2、多写了
一个 1.0。**连带三处错误**：混合带三带错、线B线内 q25 错（.5312 应为
.2438）、072① 复判方向整个翻转（"解除"实为"延续"）。
更刺眼的是：**F2 自己的自测锚算的就是正确池（PASS），但锚没绑定代码主体
输出**——锚对了、主体错了、门全绿。

## 第四幕 · 实证根因（不是手滑，是仪器量纲缺陷）

逐条溯源池内 28 条读数：**至少四类量纲混装**——检出率（1.0，高=好）、
假采纳率（0.0，低=好！）、占比（.375）、参数值（ε*=0.1）在同一池里算分位。
两条铁律书证：该列的操作定义从来就是"机测 vs 自报"（客观性维度），
从未承诺量纲统一；且预注册层面曾有语义写反的前科。
**结论：双峰不是"某条线行为异常"，是池构成伪影——分位门在混装池上方向性
失效。**

## 第五幕 · 结构修复与议题消解

用户拍板拆池：四亚族（比率-成功/错误-代价/占比-构成/参数终值出池）+
28 条逐条打（量纲类，实验情境，方向性）三元组标签+绑定断言（标签完整性
断言+负测试）。拆池重判：线B线在 M1 亚族 q25=1.0 高于带上沿（好方向
无异常）——**"线间分歧"消解于分类学，072① 议题关单，不留分立预案**。

## 教学要点

1. 分歧监控的价值不在"抓到线间差异"，而在"暴露仪器自身缺陷"——本案最终
   修复的是分位门的量纲假设。
2. 验收必须独立复算（池错误是外来验收抓的，线内自测门因锚未绑主体而放行）。
3. 修复升结构：单点更正（v4.1）→ 结构修复（v5 拆池）→ 预防闸门（标签
   完整性断言+负测试）——失效沿强制力阶梯向上搬。
4. 诚实处置：错误首版 git 留痕不抹、错误通报原件不改写、更正件并读。
