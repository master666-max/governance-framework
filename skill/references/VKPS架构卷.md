## 第零章 · 这套架构在解什么问题

不是"如何管理一个项目"，而是一个更难的组合：

| 约束 | 后果 |
|---|---|
| **C1 生产者不可信** | AI 会话会幻觉、会过度声称、会确认偏差、会跨会话失忆 |
| **C2 生产者多、并发、无共享内存** | 没有一个"大家都知道"的状态；任何共识必须落在盘上 |
| **C3 产品是知识，不是代码** | 无法靠"跑一遍测试"验收；真值本身需要被构造出来 |
| **C4 人不可能全程在场** | 裁决必须稀疏、可延迟、且一旦做出就不可被下游悄悄稀释 |

**C1+C3 是这套体系一切设计的源头**：因为产品无法自动验收，所以必须把"可验收性"
前移成**结构性属性**——让每一条断言在写下时就自带足以被陌生人机械复核的信息。

一句话概括这套架构：**用不可信的生产者，产出可被不在场者复核的知识。**

## 第一章 · 三条公理（地基，其余全是推论）

### 公理一 · 可复核性（Verifiability）
> 任何断言必须能被一个**当时不在场、没有任何上下文**的人，仅凭盘面机械复核。

推论：断言必带 `file@commit:line` + ≤200 字**逐字摘录**（不是转述）；
外部自报数字必须显式标 `EXTERNAL-CLAIM`（与实测事实分离）；
文献只录盘上文字，**禁止用训练记忆补内容**。
（源：`PROMPT-SPEC-v2.md:31-55` R2/R4/R5）

### 公理二 · 不可改写性（Immutability）
> 历史记录只能追加与超越，永远不能修改。

推论：账本 append-only；主键幂等（内容哈希）；修正走 **supersede 侧表**追加而非改行；
勘误"不改账本行，仅 incident-log +1 / delta-baseline +1 / audit-log 还原"；
整文件 sha256 前后登记 → **行数减或哈希变即 HALT**。
（源：R7；`append2.py:10-11,19-30,36-53`；`errata-log.md:10-14`）

**为什么这条比看起来重要**：它把"掩盖错误"变成技术上不可能。
任何改写都会破坏哈希链，被下游接手会话的自检机械检出。
错误因此**只能变多、不能变少**——这是诚实的结构性保证，不是道德要求。

### 公理三 · 裁决权归人（Human Sovereignty）
> 矛盾只登记不裁决；裁决权归人；且人的裁决必须落盘。

推论：AI 遇冲突 → 入 `CONTESTED`，**不合并、不择一**；
HALT 的唯一恢复凭证是**人写的** `HALT-RESOLVED`，AI 禁止自行解除；
CORE 扩核**逐次**须用户批；口径变更以"用户令"形式入账；
禁止 AI 自报级别。
（源：R3/R9；`PROMPT-SPEC-v2.md:183`；`INCREMENTAL-LOG.md:966-994,1451`）

**配套的反向授权**：AI 有**叫停权**。这是关键的非对称设计——
AI 不能决定"继续"，但可以决定"停"。停止权下放、推进权上收。

              ↑ 把失效转成规则

## 第三章 · L2 寻址层：内容寻址取代位置寻址

### 问题
被审计对象**解冻可写**之后，"当前文件"成为移动目标。
所有基于 `路径:行号` 的引用都会静默失效——而且失效时**不报错**。

### 机制
1. **纪元划分**：以一个不可变 tag（`zero-point-v1`）为界。
 - **冻结纪元**断言：锚点格式不变，但解析基准**一律是 tag 树**
  （`git show <tag>:<path>` 第 N 行）。tag 指向不可变 commit 对象 →
  **工作树怎么改都不影响它** → 冻结断言永不失效。
 - **实验纪元**断言：锚点升级为 `file@commit:line`，每条断言钉死其生成时的 commit。
2. **禁令**：对可写文件使用裸路径锚 = 违规（该项目定为红队"伤"级）。
3. **锚点可解析性自检**：使用前先核 `工作树 blob == 该 commit blob`
 （`git hash-object` vs `git rev-parse <c>:<path>`）。相等才说明"盘面态 == 锚态"。
4. **脏工作树不作锚**：未提交的改动无法被第三方解析，故"交付即入库"。

### 可迁移要点
- **锚点必须绑定到内容，不能绑定到位置。**
- **纪元边界要用不可变对象（tag/快照/发布号）钉死**，不要用日期。
- **锚点协议本身也会漂移**：该项目发现协议声称 `git show` 对 gitlink 内部路径有效，
 实测不成立，修正方式是"**不改写原文，仅登记**"（严格遵守自己的公理二），
 但协议修订**悬置未做** —— 这是一个诚实登记但未闭环的漏洞。

### 我亲历的反例（值得写进任何迁移手册）
**双仓拓扑盲区**：`大审查/` 在上级仓中是 gitlink（mode 160000），发布区文件属**上级仓**。
我在子仓跑 `git log --all -- "*RELEASE*"`，得到"全历史仅一条"，据此判某引用"悬空"。
事实上被引件在上级仓，且有 commit 锚、有提交信息逐字印证。
→ **教训：跨仓/跨 submodule 拓扑下，"全历史"永远是"某一个仓的全历史"。**
任何"不存在"结论之前，必须先问"我搜的是哪个命名空间"。

## 第四章 · L3 记录层：账本的数据模型

### 账本（claim ledger）9 列
| 列 | 语义 | 设计要点 |
|---|---|---|
| `claim_id` | 主键 | = `sha256(canon路径 : 行号 : 摘录前80字)` → **幂等**：重扫同句自然同 ID |
| `location_anchor` | 锚点 | 实验纪元 `file@commit:line`；冻结纪元 `路径:行号`（按 tag 解析） |
| `verbatim_quote` | 逐字摘录 | ≤200 字，**逐字**不转述 |
| `experiment_id` | 宇宙/家族前缀 | 命名即分类（见下） |
| `type` | 断言类型 | 五类裁决树 |
| `status` | 生命周期态 | 五态 |
| `source_type` | document / dialogue | 区分盘面件与口头令 |
| `superseded_by` | 恒空 | **状态翻转不写这里**，走侧表 |
| （登记用）整文件 sha256 | 完整性 | 每次 append 前后各记一次 |

**幂等主键是整套体系最优雅的一处设计**：它把"去重"从人工判断变成哈希碰撞，
使"重复提取"这个必然会发生的操作**变得无害**。
该项目里表现为 append 阶段的"碰撞跳 1"——按规则跳过并计数，**不算错误**。

### 断言类型：五类裁决树（首中即停）
`hypothesis → result → verdict → parameter → method`
顺序即优先级：一条断言按此序判定，第一个命中的类别就是它的类别。
**为什么要"首中即停"**：避免同一条断言被归入多类而重复计数。

### 生命周期：五态 + 裁决优先序
`superseded > contradicted > refuted > verified > open`
关键语义：**`status` 记的是"写下当时的状态"**，不是"当前状态"。
态的翻转**不改原行**，而是向 `supersede_log.csv` 追加
（`old_id / new_id / reason / ts`）。
→ 于是账本同时保有"当时怎么认为"和"后来怎么改判"两条历史。

### 侧表族（append-only 的配套）
| 侧表 | 角色 |
|---|---|
| `supersede_log.csv` | 断言态翻转（替代改行） |
| `incident-log.csv` | 事故台账（描述摘录 / 机制 / 死因分类） |
| `audit-log.csv` | 锚点抽检记录（谁抽、命中否） |
| `delta-baseline.csv` | 各账本行数 + sha256 快照基线 |
| `errata-log.md` | 勘误正文（含"给第三方核验者的注"） |
| `red-team-input-manifest.csv` | 红队可信输入的完整定义（排除集 + 复现命令 + 终态哈希） |

**"给第三方核验者的注"是一个值得抄的细节**：勘误会让盘面哈希与 manifest 不一致，
于是**预先写下一段解释**，说明这个不一致系授权追加而非篡改。
即：*主动为未来的怀疑者准备好证据链*，而不是等他发现异常再辩解。

### 命名即分类（编号体系 = 制度记忆）
`experiment_id` 前缀就是宇宙/家族：`REAL / SIM / DB- / AUDIT2 / CBB- / KB-TASK-n /
F1~F4 / 方法论- / E-J4 / P-B2 / W- / v3.10 …`
规则是"**沿文内原号、不猜**"——即编号的权威源是产生它的那份文件，不是中心分配器。
统计时按前缀聚合即可得到家族画像，无需额外索引。

缺陷/工单编号同理分工：
`P-0xx`=pitfalls（事故教训）· `K-0xx`=内核修复工单 · `W-x`=跨线工程工单 ·
`S#/I#`=红队伤级/痒级 · `DX-#`=验收套件诊断段 · `F##`=失败教训 · `B-#`=第三方漂移项。
**防撞号制度化**：曾出过"两代同号异义"，此后立"编号资产前缀化"规则。

## 第五章 · L4 生产层：责任田 + 文书流

### 分区模型
每块"责任田"= 一个目录 = 一个独立 AI 会话的**唯一可写区**。
- 一切新建只落本田；跨田引用一律只读。
- 档案类目录（历史交付物）**永久只读**，可加 `FROZEN-READONLY` 声明，解除须人令。
- **无锁**：靠分区约定 + append-only + "先读后写、撞车重读合入"。
- 无锁的代价有实证：曾出现后台进程恢复后 `mv` 与多进程交叉写互相覆盖，
 导致对照件丢失。**分区不能防同一田内的自我撞车。**

### 文书流（替代会议与 IM）
```
下发单  ──→  回执（= 线内 commit）  ──→  验收  ──→  知会单（门控解除）
   ↑                                                    │
   └──────  补正单（发现缺陷时）  ←─── 通报（一对多）  ←──┘
```
- **下发单**：抬头 `（审计区 → X线，日期）` → 排期依据/门控声明 → 主件（编号动作+判据）
  → 通报/边界 → **回执条款**。支持"**预派发 + 门控**"：单子先发，
  但写明"执行前置条件=X 落档并验收；在那之前本单不执行，仅接单登记"。
- **回执 = commit**，不是消息。commit message 里引用账本条目即生效。
- **下发副本原样收编**：收件方把下发单**原文复制**进自己的田，
  "不改动、不转写" → 消灭转述失真。
- **补正单四段式**：事实（git 取证）/ 补正动作（**给多选项**，含"若不一致立即停手上报"）
  / 影响范围界定 / 回执。
- **收件动作标准化**（PT-018 开工三步）：
  ① `git log --oneline -5 -- <本田路径>/` 扫收件箱
  ② 领派发（出具接单回执，原样收编 + 执行）
  ③ 核状态 —— **自报"没收到/已完成/无在途"之前必查 git log；
  状态自报以盘上链为据，不以会话记忆为据**。

第③步是针对 **P-019「被动投递陷阱」** 的解药：投递 = 田内新增文件，
而线会话收尾后**无人扫描**，新会话不查 git log 就会自报"没收到"
（实证：线会话自报未收到，而 git 链显示早已收编执行）。
→ **可迁移定律：被动投递系统里，"没收到"是最不可信的自报。**

### 预注册（pre-registration）四条款 + 一
把"先锁判据后跑"变成可机械检查的清单：
1. **门值引带并锚定**：标量门必须引自外部仪器（带表）的分位数，
 写明带表实物路径 + 锚 commit；"q25 保守门"或"整带无为区"**二选一且显式声明**。
2. **判据-实现映射**：每条判据在编码前**指认它读哪个返回值字段**。
 （针对一次"判据写的和代码读的不是同一个东西"的事故）
3. **双侧分支**：命中 / 未命中**两条后续动作都要预注册**。
 单点赌注禁止 → "未命中"被预先变成一个有产出的动作，事后无换判据空间。
4. **浮点容差**：边界判定 ≥1e-9。
5. **（后增）豁免清单强制**：任何"逐位一致 / byte-identical"宣称
 **必须随附豁免清单**（包装分隔行 / CRLF / 计时列 / 已知仪器差）；
 无注记者按**可机械否证**处理（sha256 不等即证伪）。

"缺一不受理"——即预注册本身有个准入门。

**副本分发**：SOP 复制成 8 份（根级 + 7 田），逐字节相同。
动机：被动投递模型下**引用外部路径 = 不可达**，故物理复制到田，
"新会话扫文件夹即见"。降本设计：**"各线下一份预注册即视为采纳，无需单独回执"**
——用**行为采纳**替代 8 份签收。
代价（实测）：8 处手工同步、无自动校验；某次修订后 7 份 tracked 副本全部处于
`M`（已写盘未提交）状态。
→ **可迁移定律：副本分发换来可达性，付出的是同步一致性；必须配生成化或对账探针。**

### 外部仪器：带表（band table）
- 是**脚本 + 预承诺规则**：计算前锁定 V1–V6 规则，附 selftest 手算锚。
- 按 effect family 分族，输出 q25/q50/q75（线性插值）。
- **全池计算，无 LOO 剔除** —— 明文写"带是仪器不是回测"。
  （即：仪器的定义不能随被评测样本变动，否则它就不是仪器）
- **重锚**：带值绑定到一个可寻址 commit；预注册须显式引用"重锚 <hash>"。
- **不追溯**："已完成预注册一律不追溯" —— 带值变了也不许回头改判据。
- **自我不利登记**：带值变动 |Δ|>0.05 时强制通报 + 影响评估，
 并**主动登记哪个既有判定会因此翻转**（即使对自己不利）。
- 由**独立的一块田**维护（不是由使用方维护）→ 仪器与使用者分离。

**这一层解决的是 HARKing（事后挑判据）**：把门槛从"作者自选数字"
变成"外部仪器读数 + 锚 commit + 不可追溯"。

### 确定性双跑
- 动机：语言运行时的 `hash()` 随机化、容器迭代序不保证、全局随机吃系统熵
  → 同一份代码两次跑出不同结果。**双跑是"结果可归因到确定字节"的唯一证明。**
- 对照件命名规范化，且**必须归档进 commit**（"在案为验收前置"）。
- 判据：逐行一致，**唯一允许差异 = 预先白名单的计时列**；
 豁免是"手册层按实验编号的预置白名单 + 指标降级（只写量级区间）"，
  **不是事后开口子**。
- 曾出事故：commit 宣称 `DETERMINISM=PASS`，但六处均查无对照件。
 定性为与"假全绿"**同构** ——「**与历史格式吻合的宣称需要 artifact 支撑**」。
  → 处置不是补一句话，而是补跑 + 归档 + 立"**双跑对照原件永不删除**"纪律。

### 主门与判定行归档
- 验收目录是**自包含复跑单元**：被测件 + 探针 + 验收套件 + 历史 log 全在一处。
- **双门口径**：主门（关单门，PASS 32 / FAIL 0）+ 回归面（旧套件 patched，
  已知若干 FAIL，**仅监测不关单**）。分开口径避免"旧账压新门"。
- **诊断段（DX）**：每一项对应一个历史缺陷编号，
  "**任一变红 = 对应修复回归**" → 诊断段是**回归探测器**，不是验收门。
  且明文写"当前预期红，内核修复后应转绿并可晋升为正式门"（门可以升级）。
- **测试身份打印**：套件头打印被测件的 sha256 → **防验错文件**。
- **判定行归档**：切 canonical 的前置条件是"主门全绿 + **判定行归档**"。
  为什么不只 exit code：见第七章"假全绿"。

### 生成文化（make_*）
- 产物不手改，由**生成脚本 + 补丁链**从上游版本按行切片搬运（byte 级忠实）。
- 每处改动前 `assert old in s, "锚点未命中"`；补丁生成器用 `assert new.count(old)==1`
  → **锚点唯一性断言**。
- 记账方式："**11 补丁全锚点命中**"、"重生成哈希 X 与接替前**逐字节一致**（可复现）"。
- 防四种失效：①手改不可复现 ②修订在再生成时静默丢失
 ③补丁静默未应用 / 多处误应用 ④移植走样。

## 第六章 · L5 提炼层：增量制图管线

**目标**：把一段时间内产生的全部文档流，提炼成结构化断言库，且**可复现、可审计、方差已知**。

### 六阶段
| # | 阶段 | 输入 | 判据 | 输出 |
|---|---|---|---|---|
| ① | **scan** | 上圈收官锚 .. 开圈 HEAD 的**双仓** `git diff`（仅 A/M，**D 跳过**） | EXCL 子串过滤（四模式） | 候选文件清单（1193 变更 → 49 md） |
| ② | **materialize** | 候选清单 | `git show <开圈commit>:<path>` 导出到沙盒；失败记 `MISS` | 48 件 / 5483 行，贪心均衡分块（~1000 行/块） |
| ③ | **extract** | 沙盒块 + 操作定义（DEF） | 子代理**禁读账本/主区/互联网**；行号由工具机械裁定；**锚点不中整条拒**；密度偏离回审；**自检全 PASS 才交** | 每块一个 jsonl |
| ④ | **verify** | jsonl | 主会话逐批重跑校验脚本（枚举 / manifest 归属 / 锚点命中 / ≤200 字，任一 fail 即 exit 1）**+ 人读抽验** | 6/6 机械 + 6/6 人读 |
| ⑤ | **merge** | 各批 jsonl | 锚点复核 + **幂等** + 去重；失败弃条并计 `anchor_fail`；全部锚定开圈 HEAD | 537/537 零失败 |
| ⑥ | **append** | merge 结果 | **碰撞跳过 + 只追加**；新行逐条锚点复核 | 账本 9577→10113，跳 1，536/536 pass |

**"EXCL 四模式 / 副本件机械排除"**：把"同一文书的派发副本"排除掉，
否则一份下发单被 8 个田各收一份就会**重复入账 8 次**。
同类先例：审计区自己产出的文件不入账（避免自指膨胀）。

**为什么物化到沙盒**：提取者读的必须是**开圈 HEAD 的冻结副本**，
不是活的工作树 —— 否则提取期间文件被改，锚点就骗人。

### 双盲交集定级（这是提炼层的核心）
- **pass A**：窗口期由独立代理对目标文件**盲提**（盲 = 按 DEF 禁读账本、禁读主区）。
- **pass B**：同一批文件在正常制图流程里再提一次。
- 两路**互不可见**。
- **交集判据**（三个条件同时满足）：
 1. 同一文件；
 2. `|行号差| ≤ 3`；
 3. **包含度 ≥ 60%** —— 定义为"短串被长串包含的比例"（`difflib` 匹配块 / 短串长）。
- 配对方式：按包含度**降序贪心，一线一配**（避免一对多）。
- 定级：`type` **且** `status` 双一致 → **CORE**；否则 → **CONTESTED**。

**一个必须记住的教训（该项目自己踩过后修的）**：
早期版本误用**对称** similarity ratio，导致 3 条"承重行"漏配。
修正为非对称的"短串被长串包含比例"。
→ **可迁移要点：文本匹配度量必须匹配任务的不对称性**
（一方是精炼断言、另一方是原文长句时，对称度量必然失真）。

### 三级置信度（这是"记忆库低层"的分级骨架）
| 级 | 条件 | 允许的引用形式 |
|---|---|---|
| **Tier-1 CORE** | 双提取 + 双判定一致 | 可给**点估计**；引用标 `[CORE@圈-窗口]` |
| **Tier-2 CONTESTED** | 存在性双证实、**判定分歧** | 引用**必须带分歧注记** |
| **Tier-3 SAMPLE** | 单轮提取 | **只许区间**，禁止点值 |

晋升：新断言默认 SAMPLE，双边命中升级；**扩核逐次须人批**。
CONTESTED 入核**不免终裁**（分歧还在，只是登记得更权威）。
**降级机制：盘面上未找到**（这是一个真实缺口——只有升没有降）。

**入核前的三重核验**：机械 quote-in-line（1762/1762）+ 匹配全过 + **人读 20/20**。
第三重不可省，因为——

### 交集的效力边界（最重要的元层洞察之一）
> **交集只消灭"提取存在性方差"，不消灭"共同理解错误"。**

两路都读错同一个词，交集会给出一个**高置信的错误**。
所以：①必须有人读抽验作为异质通道；②判定分歧**不合并**，入 CONTESTED 保留分歧本身。
（分歧是信息，不是噪声。）

### 方差纪律（V1–V4）
- **V1**：账本是**断言样本，不是完备枚举**。→ 任何"总共 N 条"都是抽样结果。
- **V2**：统计一律给**区间**，点值必须与区间同现；**单独点值按违规计**。
- **V3**：行用全集，禁用交集子集冒充全集。
- **V4**：回炉 ≤2 轮，之后**固化为已知方差**（不许无限重跑到满意为止）。

区间的算法值得抄：**点值 × 首轮实测方差因子 [0.795, 1.358]，取 floor/ceil**。
即方差因子**来自一次专门的方差实验**（同一批材料跑多个变体），不是拍的。
例：有效断言 10,009 − 参考件 1,277 = 8,732（点值）→ [6,941, 11,859]（区间）。

**"拆出"的处理很讲究**：某家族经人裁决"与本实验非同路，只可参考" →
**账面行保留不删（公理二）**，但**剔出统计与托举面**。
即：*排除发生在口径层，不发生在数据层。*

### 圈的节律
- **开圈唯人令**。
- **开圈仪式 = 基线重钉**：扫描窗 = `上圈收官锚 .. 开圈时双仓 HEAD`；
  **开圈 HEAD 即本圈全部入账的锚定 commit**。
- **收官 = append + 收官报告（DELTA-REPORT）+ 账本条目 + 预告下圈基线**。
- 收官报告固定结构：账本对照 / 新增画像 / 高价值项 / supersede 动态 /
  CORE 预演呈报待批 / 下圈基线 / **复现命令**。
- **为什么每圈重钉**：窗口首尾相接 → 既不漏提也不重提；
  且所有锚点钉在同一个 commit 上 → 整圈断言可一次性机械复核。

### 判据外化（R10）—— 提炼层能成立的前提
> **判据必须先写成 guide 文件，再执行。**

理由（实测得出）：隐性知识是可复现性的头号敌人。
首轮做过对照实验：盲建组 vs 有隐性指南组，**差额即全部 diff 不一致**。
所以提取者的"唯一规则来源"是一份持久化的操作定义文件（DEF）+ 提取者指南，
而不是会话历史里的口头约定。
→ **可迁移定律：任何要交给另一个 agent 执行的判据，必须先物化成文件。**

## 第七章 · L6 免疫层：失效如何变成规则

### 红队机制
- **独立会话，与制图师零共同上下文**；输入**只从盘上来**（manifest 定义完整输入：
  已抽 claim_id 排除集 + 复现命令 + 终态哈希）；**只报告不修复**。
- 抽样用**盐值 sha256 决定论排序** → 第三方可机械重放同一份样本。
- **三级分类**：
 - **毒**（污染 / 编造）：≥3 触发 `DOWNGRADE-TO-DRAFT`（整份产出降级为草稿）
 - **伤**（须勘误）：编号 S1、S2…
 - **痒**（登记转下圈）：编号 I1、I2…
- **回流成规则**（每条伤级都要落地）：
 S1（自指计数过期）→ 立"自指计数一律带时点标注"；
 S2（复现命令硬编码绝对路径穿透沙盒污染 audit-log）→ incident 方法论-02 + 下圈预注册素材；
 "违反区间规则按伤计" → 写进 gate 硬规则并被锚点协议引用。

### 事故 → 编号 → 规则 → 代码断言（完整转化链，三个实例）
1. **E81「自我美化零触发」** → 体系级红线「judge 数字永不对外」
  → **类型断言** `JudgeScore`（`__str__` 返回 `<judge:internal-only>`）
  + 独立 `truth()` 通道绕开 judge + 对外报告结构体**无 judge 字段**。
2. **E149「mutate_dead：增益恒 0 的假安全」** → 新增活跃度探针
  → **代码断言**：活动计数只统计核心维度；drift 后无适应即注册致命危险。
3. **P-020「再生成静默回退」** → 规则「发布件的手工修订必须沉淀为生成链补丁」
  → **机械验证**：补丁入链后"11 补丁全锚点命中"、重生成哈希逐字节一致。

**转化链的终点必须是"机械可查"的那一级**，停在"提醒大家注意"就算没转化完。

### P-020 定律（我认为这是整个体系里最可迁移的一条）
> **生成物上的任何手工修正都是悬空态。**
> 原话：「部署文件的手工层永远在模板再生成的水线以下。」

两次实例：①参数升级后未进补丁链，再生成时**静默回退**到旧值；
②引擎重装按模板重写配置文件，**手工增补的授权节被抹掉**。

整改方向永远是**把修正上移到输入端**（生成器 / 模板 / 补丁链）+ 锚点断言，
而不是"下次小心"。因为**再生成是常态操作**，手工层必然被水淹。
配套检查："**P-020 三查：修订后对旧锚点 diff，而非只对新锚点自测**"。

### 假全绿事故：五步因果链 + 四条规则
**因果链**：补丁锚点缺口（改返回值元数未覆盖全部解包点 → 新旧赋值共存 → 运行崩）
→ 只做程序化计数、**从不人读 log 尾**（traceback 就在最后几行）
→ `exit=1` 被"旧先例类比"错误归因
→ **"31/0" 与历史三轮数字全吻合**，被当成复现成功
→ 宣称写进 commit。

**分层根因**：「验证工具自身的变更，没有与被测物同级的事故防线」——
**该线已三次栽在验收工具上**。

**四条规则**：
1. **签名变更协议**（验证工具的接口变更要走与被测物同级的流程）
2. **验证工具变更四查**：①人读 log 尾 ②判定行存在 ③`exit==0`
 ④**断言计数 == 套件头声明数**
3. **exit 语义表**：**禁止跨套件类比** exit code 含义
4. **历史吻合警报**

**"数字与历史吻合"为什么是危险信号（机理）**：
崩溃点确定 → 每次都崩在同一处 → 崩溃前的部分计数**恒定** →
"数字稳定"恰恰是**冻结在同一失败点**的签名。
而"全绿"是**最不引发人读细节的状态** → 确认偏差被反向利用。
→ **可迁移定律：稳定的数字有两种来源——系统健康，或系统死在同一个地方。
必须用"断言计数 == 声明数"和"人读判定行"来区分二者。**

### 静默失败核验检查单
11 条，三族：**A 标定与判据**（尺子自身失准）/ **B 口径与混杂** / **C 可复现与工程**。
每条结构 = **失败模式 → 核验问题 → 对应位置**。
用于审计与预注册自检。
典型条目："判据是否对**恒真/恒伪退化**免疫（恒 1.0 = 探针已死）"。
与"假全绿"是**同族问题的两个独立产出**（二者无交叉引用——
这本身说明缺少"护栏之间的互引索引"）。

### 运行期自监控分层（系统监控自己）
```
L0 类型红线        违反红线的代码写不出来（见下）
L1 免费锚定探针    固定策略 × 固定任务集 = "世界温度计"；窗口跌落 > 阈值 → 报 drift
                   ⚠ 已知边界：无法区分"世界漂移"与"判官漂移"，故必须以盲评为前置
L2 付费真值审计    CUSUM(k, h)；μ0 冻结（明文废除"扩张均值"——
                   理由：扩张均值 = 基线跟随漂移，是同族变体，检不出慢漂）；
                   轮换不洗累积量；报警后走判别式：当前最优 > 当前+δ → 判腐坏并回退；
                   连历史最优也救不了 → 连续 ≥2 次才判 drift 重锚
L3 活跃度探针      窗口 N 代内核心维度变更数 ≥ 门槛；drift 后无适应 = 致命档
L4 溢出探针        有符号残留超阈报警
L5 停摆响应        连续无采纳 → margin 减半；有采纳即回升（防单向棘轮）
L6 汇聚响应        危险集 ≥ 阈值 → 变异幅度降档
横切：双账本（探针预算 / 判官注意力），任一耗尽 → 结构化停机
横切：唯一出口报告，含危险/报警/元层签名校验
```

**几个设计判断值得单独抄**：
- **"μ0 冻结"的理由**是这套体系里最漂亮的一句：
  *扩张均值是基线跟随漂移的同族变体* —— 用会跟着漂的量的均值当基线，
  等于让尺子跟着被测物一起热胀冷缩。
- **L1 探针的已知边界被写进代码注释**："不能区分世界漂移与判官漂移，须盲评就位"。
  → **护栏自带效力边界声明**，防止下游把"探针没报警"当成"没问题"。
- **"轮换不洗累积量"**：轮换会改变表面状态，但累积统计量不清零，
  防止"用轮换把报警洗掉"。
- **单向棘轮是真实缺陷**：危险集只增不减（无 discard/clear）→
  3 类瞬时危险累积后变异幅度**永久**腰斩，即使后续回退/重锚成功也不恢复。
  → **可迁移定律：任何"降档保护"都必须配对称的"恢复条件"，否则它是个单向阀。**

### 自演化安全架构（让系统改造自己而不失控）
1. **三层写权限**：
 - **Meta 冻结**：系统**无写方法**，只有人侧 `with_()`；改即重签，可校验。
 - **Policy 可自由演化**：策略层是演化发生的地方。
 - **Entry 可写**，但**整理用真值、不用判官**（防止判官偏好被写进数据）。
2. **能力式约束 > 检查式约束**：
 廉价筛选的返回类型是 `Literal["reject","unknown"]` —— **类型上不存在 "accept"**。
 原话：「**违反红线的代码写不出来，而不是写了会被拒绝**。」
 → 于是"用廉价筛选来采纳"这种误用**在编译期就不成立**。
3. **判官数字的封装**：`judge()` 返回一个**结构体而非 float**；
 取数字必须走 `.internal`，且其 `__str__` 是 `<judge:internal-only>`；
 内核保证 `.internal` **只用于档案排序，不进入任何对外报告**。
 → 防的是"内部评分被当成质量指标对外汇报"（曾实测膨胀 349×）。
4. **盲评**：判官看真值的比例可配，盲评模式下把表象权重压到极低（0.05）
  → 用参数化方式**限制**判官被表象俘获的程度。
5. **审计专用真值通道**：`truth()` **绕开 judge 通道**，是独立的读数路径。

### E81 红线（整套体系哲学价值最高的一条）
> **如果外部参照是通过同一个有缺陷的观测通道获得的，它不构成外部性。**

背景：曾以为"锚定集 + 元层签名 + 异质标注"构成了外部校验，
但在表象污染下**审计零触发** —— 因为锚定集的判断也来自同一个判官。
于是旧结论被推翻，出路是：**真值抽样必须周期性由人直接执行**。

→ **可迁移定律：设计任何"交叉验证"之前，先问一句
"这两路是否共享同一个缺陷通道？"**
共享通道的两次测量不是两次测量。这条同样适用于：
用同一个模型做生成和评审、用同一份埋点做 A/B 和监控、
用同一个抽取器做双盲两路（此时"双盲"只盲了上下文，没盲模型偏差）。

### 两轴授权模型（能力 × 信任）
- **两轴正交**：**L 能力轴**（L0–L9，由安装决定"能做什么"）
  × **E 信任轴**（E0–E4，运行期授权"允许做什么"）。
 核心命题：「**档位 ≠ 授权**」。
- **E0 禁演** → **E1 受限**（仅参数演化 + 停摆监控；前提 = 金标三尺分离 / 人侧锚定 / 预算账本）
  → **E2 受控**（+ 重组算子须过参数稳定门 + 实测重要度）
  → **E3 半自主**（+ 变异引擎循环；人类令牌 = 元层签名入口；锚定审计检出即**自动转只读**）
  → **E4 全栈**（+ 内省信号仅作行层数据源；前提 = 盲评隔离 + 整理用真值标准）。
- **通用红线（不随档位放宽）**：判官数字永不对外 / 元层人侧签名、系统无写方法 /
  **自动采纳必须可回滚**。

→ **可迁移模式：把"系统能力"和"授予系统的信任"拆成两个正交轴，
授权档位挂**前提条件**（不是挂时间或进度），并保留一组不随档位放宽的硬红线。**

### 护栏冲突的元层登记（风险守恒）
实测发现：**加准入门把受伤样本从 4 个降到 2 个，但换成了另外 2 个**
（`[5,8,11,13] → [2,4]`）。裁定原文：
> 「**门 reshuffle 风险，不消灭风险**；出路 = 观测位置 + 语义修复。」

同族的元层洞察还有：
- 锚定探针的"加权提升"在判官漂移下**反而使表象权重翻倍** → 必须以盲评为前置；
- margin 只降不升 → 晋升门**沦为纯噪声**；
- σ 地板缺失 → 恒值 warmup 使 σ→0 → z 值饱和到 245，
  **16/16 档全触发但判读粒度归零**（假灵敏）；
- **未标定的阈值本身就是伤害源**（α=0 时净损 0.127）。

登记机制：**预注册判据先冻结 → PARTIAL/INCONCLUSIVE 如实判定（不硬凑成 SUPPORTED）
→ 矩阵新增裁定行 + 边界注记 → 教训条目化**。
→ **可迁移定律：每加一道护栏，都要问"风险去哪了"，而不是只问"风险少了多少"。**

## 第九章 · 强制力阶梯（护栏分级）

```
① 类型级不可表达   ← 最强：违规代码写不出来
② 运行时崩溃       ← assert / 构造校验，违规即挂
③ 机械可否证       ← 哈希、锚点、计数：第三方可一键证伪
④ 流程门           ← 不过就不能进下一步（但门可以被人跳过）
⑤ 文档纪律         ← 靠自觉 + 事后抽检
```

**实测重心分布**：
- **内核代码内**偏 ①③ 级（类型红线、签名校验、锚点断言）——最强。
- **跨线流程**偏 ④⑤ 级（预注册门、判定行归档、四查、exit 语义表）——较弱。

**该升级而未升级的（真实缺口）**：
- "验证工具变更四查 / exit 语义表"**未编码进套件自身**（可机械执行，却靠人做）→ 应从 ⑤ 升到 ②。
- append-only **无 git hook 拦截**，强制力来自"续跑会话哈希自检 + 事后可恢复"→ 可从 ⑤ 升到 ②。
- 防漂移检查**无固定周期**，触发方式是"人令"→ 应从 ⑤ 升到 ④。
- 锚点抽检**既无记录也无豁免声明**→ 抽检纪律纯靠自觉。
- CORE **只有升级没有降级**规则。
- 8 份 SOP 副本**无自动一致性校验**。

→ **可迁移定律：给每条护栏标注它现在在哪一级、应该在哪一级。
"写在文档里的纪律"不是护栏，是待办。**

## 第十章 · 已知薄弱点（诚实登记，不粉饰）

1. **登记层自指性**：任何"数数"结果一落盘就过期（报告落盘即改变被计数集合）。
 已立"自指计数带时点标注"规则，但**结构性问题无法根除**。
2. **消息总线自身会错序**：账本追加曾因编辑锚点踩踏致条目乱序，靠事后脚本重排。
 教训"追加锚点必须唯一化到文件尾"**只进了操作记忆，没进机制**。
 → 我自己也踩了：并发追加导致**条目 077 撞号**。
3. **双仓/多命名空间拓扑盲区**：见第三章反例。**"不存在"类结论最高危。**
4. **无锁并发的自我撞车**：分区能防跨田冲突，防不了同田内多进程/后台任务覆盖。
5. **副本分发的同步税**：可达性 ↑、一致性 ↓，且无自动校验。
6. **协议修订悬置**：锚点协议中被实测推翻的条款"不改写原文、仅登记"，
 但修订**一直没做** → 新读者会读到已知错误的条款。

8. **第三方审计的覆盖边界会伪装成全量结论**：这是我这次最大的教训，
